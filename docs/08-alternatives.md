# 08 备选方案

主方案（本项目）用主机驱动把桌面按 JPEG 流推过来，是**真正的扩展显示器**。
如果遇到某些限制（主机装不了驱动、要跨 macOS、要 60 fps 高动态画面），
可以考虑下面的备选方案。

## 方案 B：USB 网卡 + 远程桌面/串流

把泰山派枚举成一块 USB 网卡（RNDIS/ECM），设备上跑一个全屏的 VNC/RDP/串流客户端，
连到主机的虚拟显示器。

```
主机 ──USB(网卡)──▶ 泰山派 ──VNC/RDP 客户端──▶ DSI 面板
```

设备端加一个 gadget function 即可（不用写新程序）：

```bash
sudo modprobe usb_f_rndis
# configfs 里给同一个 gadget 增加 functions/rndis.usb0 并链到 configs/c.1/
# 之后板子会多出 usb0，主机侧是 192.168.137.1，板子是 192.168.137.2
```

主机侧：

* **Linux**：`x11vnc` / `wayvnc` / `xpra`。要“扩展”而不是“镜像”，用 Xvfb 或
  `xpra start --start-new-commands=...` 起一个虚拟显示，再让客户端全屏；
* **Windows**：RDP（需要 Pro 版，且是会话不是扩展屏）或第三方串流工具；
* **macOS**：屏幕共享 + 客户端。

优点：

* 主机**零驱动**（RNDIS/ECM 系统自带），macOS 也能用；
* 可用 H.264 硬解（RK3566 VPU），1080p60 也比 JPEG 流省 CPU；
* 可跨网络使用（不限于 USB）。

缺点：

* 不是操作系统级的扩展显示器：Windows 下基本是镜像/远程会话；
* 端到端延迟高（编码 + 网络 + 解码，通常 30~80 ms），不适合拖窗口/画图；
* 需要主机侧开服务、配虚拟显示，折腾度高于方案 A。

**适合**：Linux 主机想要第二块“独立桌面”、或需要在 macOS 上用。

## 方案 C：参考项目的原版固件（RK3506 + 1280×452）

oshwhub 上那个 [6.2 寸 USB 副屏](https://oshwhub.com/an_ye/project_wgtodlyq) 是
RK3506G2 + 1280×452 屏，固件/APP/SDK 都开源，烧 `update.img` 就能用。

**适合**：手上有那块 1280×452 的屏和 RK3506 板子；或者只想快速体验 udisp 协议。

**不适合**：你的屏是 1080×2160 的天马屏——分辨率、lane 数、触摸 IC 都不同，
而且 RK3506 的 SDK 与泰山派不通用。

## 方案 D：UVC / HDMI 采集

* UVC（USB 摄像头）：主机把它当摄像头，不是显示器，不能扩展桌面；
* HDMI 采集卡 + 显示：需要主机有 HDMI 输出，泰山派只做“显示器”，那就不需要 USB 了。

都不解决“一根 USB 线扩展桌面”的需求，仅作对比。

## 对比

| | A 本项目（udisp） | B USB 网卡 + 远程桌面 | C RK3506 原版 |
| --- | --- | --- | --- |
| 是否系统级扩展屏 | ✅ | ⚠️ Linux 可，Windows 基本镜像 | ✅ |
| 主机装驱动 | 需要（Win IDD / Linux 模块） | 不需要 | 需要 |
| 延迟 | 20~40 ms | 30~80 ms | 20~40 ms |
| 画质 | JPEG q6~8 | H.264，可更高 | JPEG |
| 设备端 CPU | 解码占 1~1.5 核 | 硬解，占用低 | 低（小屏） |
| 分辨率 | 1080×2160 | 任意 | 1280×452 |
| 工作量 | 已实现 | 需配虚拟显示/串流 | 换硬件 |

日常办公、写代码、看文档：**A** 最合适。
要在 macOS 上用、或主机不方便装驱动：**B**。
只是想要个小副屏且手上有 RK3506 套件：**C**。
